# AGENTS.md - AI Agent Guidelines & Architecture Manual

This document provides context, technical specifications, project architecture, and verification workflows for AI agents working in the **Invaders JS** repository.

---

## 1. Project Overview

**Invaders JS** is a faithful arcade recreation of the 1978 classic _Space Invaders_. It is implemented in pure Vanilla JavaScript (ES Modules) using standard browser APIs:

- **HTML5 Canvas 2D** for rendering with nearest-neighbor pixel smoothing.
- **Web Audio API** for synthesized arcade sound effects.
- **Web Storage API (`localStorage`)** for high score persistence.

### Core Philosophy

- **Zero Runtime Dependencies**: The game runs natively in modern browsers with no external runtime libraries or frameworks.
- **Arcade Authenticity**: Authentic 1978 timing, pixel dimensions, color palettes, and attract mode screens.
- **Strict Clean Code Standards**: Enforced via ESLint (flat config) and Prettier prior to every production build.

| **Node Version**     | Node.js v18+         | Recommended runtime for Vite and npm scripts                                          |

## 5. Coding Standards & Agent Guidelines

When writing or modifying code in this repository, AI agents must adhere to the following rules:

### 1. Zero External Runtime Dependencies

- Do not introduce runtime libraries (e.g., jQuery, Lodash, Phaser, PixiJS, Three.js, React).
- Implement all game mechanics, physics, and rendering logic using native JavaScript and standard Canvas/Audio APIs.

### 2. Canvas & Rendering Constraints

- **Logical Canvas Resolution**: The internal game canvas coordinate system is strictly **672 × 768** pixels (defined by `CANVAS_WIDTH` and `CANVAS_HEIGHT` in `src/constants.js`).
- **Aspect Ratio & CSS**: Scaling is handled responsively in CSS (`style.css`). Do not hardcode CSS-pixel scale factors inside rendering math.
- **Pixel Art Fidelity**: Always ensure `ctx.imageSmoothingEnabled = false` is maintained on the 2D context.
- **Performance**: Minimize garbage collection overhead in the render loop (`requestAnimationFrame`). Avoid allocating new objects, arrays, or functions on every frame.

### 3. Audio Handling (Web Audio API)

- Modern browsers restrict audio playback until the user interacts with the page.
- Audio contexts must be lazily initialized or resumed inside user input handlers (`keydown`, `click`, etc.), as demonstrated in `Game.prototype.initAudio()` in `src/main.js`.
- Handle synthesized audio nodes cleanly; disconnect or stop nodes when finished to avoid audio context leaks.

### 4. Code Organization & State Management

- **Constants**: Store all configuration values, color codes, dimensions, storage keys, and states in `src/constants.js`. Avoid magic numbers and strings in game logic.
- **State Machine**: Follow the `GAME_STATES` pattern (`WELCOME`, `PLAYING`, `GAME_OVER`, etc.) to control transitions and input processing.
- **Storage Access**: Wrap `localStorage` calls in `try...catch` blocks to guard against private browsing or restricted environments.

### 5. ESLint & Formatting Compliance

- **Flat Config**: The repository uses ESLint 10 flat configuration (`eslint.config.js`).
- **Unused Variables**: Variables intentionally kept unused (such as catch errors or interface placeholders) must start with an underscore `_` (e.g. `_err`, `_item`).
- **Console Output**: `no-console` is disabled in ESLint for arcade logging/debugging, but production gameplay logs should remain purposeful and not spam the console on every tick.

## 6. Step-by-Step Agent Workflow

Before proposing or committing changes, follow this verification checklist:

1. **Inspect Existing Modules**:
   - Check `src/constants.js` before adding new dimensions, colors, or states.
   - Review relevant classes (`Game` in `src/main.js`, `WelcomeScreen` in `src/welcomeScreen.js`).

2. **Implement Feature / Fix**:
   - Write clean, modular ES code following existing naming conventions (classes in PascalCase, functions/methods in camelCase, constants in UPPER_SNAKE_CASE).
   - Ensure imports include the `.js` extension (e.g., `import { ... } from './constants.js';`).

3. **Verify Linter & Formatter**:

   ```bash
   npm run lint:fix
   npm run format:check
   ```

4. **Verify Production Bundle**:

   ```bash
   npm run build
   ```

   _Note: `npm run build` will fail if any ESLint rule violations or Prettier formatting discrepancies exist._

5. **Functional Verification**:
   - Ensure the canvas rendering loop remains 60 FPS without frame drops.
   - Confirm keybindings operate correctly:
     - `C`: Insert Coin
     - `Space`: Start / Fire
     - `ArrowLeft` / `ArrowRight`: Move Cannon
     - `P`: Pause / Resume
